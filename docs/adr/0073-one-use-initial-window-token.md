# One-use native admission token for the initial window

Tier 2: intermediate native authentication freshness. The iPhone native admission/preparation response provides a canonical recording session and wrapping key. A new, empty iPhone initial recording window currently obtains another forced-fresh Clerk token before binding that key and acquiring a lease and 30 reservations. Numeric virtual traces show that one mint took 328–1567 ms; the remote operation and every authority check remain necessary.

Retain the successful admission JWT only in private native RAM. It can be used exactly once for `prepare_recording_window`, dispatched before the earliest of five seconds from the original fresh mint completion, the original prepared-context deadline, and JWT expiry. The single-use local admission-context transfer can change only its native generation; it cannot reset any deadline. Native identity/revision, issuer/sub/session, account, workspace, binding, canonical admitted session, tenant, recovery scope, and request shape must match.

Only native owners can issue eligibility evidence: a newly committed empty flow, a newly committed initial-window journal with no prior request/receipt/adoption, and successful new key custody under a newly committed binding intent. The opaque proof has no public initializer, serialization, or renderer representation. Recovered journals, ambiguous writes/inserts, continuation, old servers, expired or mismatched tickets use the original fresh-mint path before wire I/O. A ticket is destructively claimed before awaiting dispatch. Any lost or unknown result retains the original durable recipe and retries through fresh credentials.

SOURCE authorization, iOS microphone authorization, source fallback, uploads, clinical reads, lease renewal, resume and recovery retain forced-fresh minting. Core and Scribe still check current local membership/provider/session/consent/context/current-key/ownership/replay fences for the initial-window request. A remote Clerk session revoked after admission can therefore create unused wrapped-key, lease and reservation metadata during this short interval; this differs from observing Clerk again at WINDOW. It cannot authorize audio because SOURCE still requires a fresh Clerk token. No authority object, token or raw key enters renderer custody, durable records, logs or Keychain through this optimization.

The five-second cap limits a dispatch, not an in-flight response. Pre-dispatch expiry is a ticket miss and triggers fresh minting. In-flight publication retains the original cancellation, identity, generation and response validation fences without adding a new five-second request timeout. There is no second ticket use after dispatch.

Fresh eligibility also requires exception-free success at all five pre-dispatch journal writes: initial flow, initial window, binding intent, binding key receipt, and initial window request. An exact successor readback after a committed-then-thrown write still completes the existing durable recovery, but marks that attempt ineligible for token reuse. Each such path sends WINDOW with fresh credentials without regenerating custody or changing its saved recipe.

The current Electron desktop recorder remains unchanged: it opts into `preparation_metadata` and sends a generic mixed-channel window under renderer-owned key custody. Its provider helper does not enable native admission preparation, and it cannot supply this native proof. macOS compilation and virtual execution check shared source compatibility; they do not establish a desktop saving.

Choose this bounded intermediate optimization over general token caching or a new pending-key protocol. It removes one measured mint without changing the canonical key-custody format, wire payloads or server policy. It does not prove all physical starts are at most five seconds.
