# Virtual lab integration and normal account verification

Tier 2, test-only live account/session automation. The owner explicitly requested
this work on October 25, including fresh agents inside this chat, two isolated
synthetic accounts, native targets, normal UI journeys and retained failures.

This sequence adds a resumable journal, exclusive native UI ownership, standard
Appium actions, hash-validated Zoom participants and normal hosted sign-in. It
does not change product authentication/consent or create memberships. The
reserved test identities have separate browser sessions and private session
stores. UI receipts carry metadata/hashes; no credentials or raw service payload
is logged or committed. Output directories must stay outside Git.

Before native execution, bind current build/source hashes, target marker,
Appium no-reset/no-terminate capabilities, actual locators and current Zoom
streams. An uncertain mutation is reconciled read-only; it is not replayed.
No synthetic source can start before actual native-backed Recording observation.
No mock/loopback result or UI-only success is a full acceptance gate.

Predeclared budgets and scope limits are in the coordinator README. Actual
model-quality work is a separate Core PR. Product UX and bounded diagnostics
are independent Scribe changes. Actions remains disabled. No production,
schema, migration, global network/audio configuration or installed app change
is authorized by this test-tooling increment.

Recovery: stop only the coordinator's synthetic browser sources, close its
Appium session, preserve any app whose recording/saved state is uncertain, and
retain the run journal and failure artifacts. Reverting these tooling files
has no product runtime effect. Exact final local commands and non-implementer
review belong on each PR after its last substantive push.

The passive-observer increment wraps existing native promises without changing
their identity or issuing product requests. It observes normal visit creation,
mount, consent admission, recorder replies and saved note metadata. Note fields,
audio URLs, credentials and authority material never enter retained receipts.
These lab exports run only after the caller independently verifies its owned
debug target. Their unit/VM tests do not prove a native UI journey.

The iOS context increment remains Tier 2 test-only session automation. A real
rebuilt-client sign-in on the owned Dublin simulator retained SafariViewService
beside Scribe, causing the previous global single-WebView check to fail after
the UI reached the workspace. Fresh XCUITest detailed metadata must now bind
one local root page to the verified app bundle. The selected page's local URL
and Capacitor bridge are checked before observer access or cleanup. Unknown,
duplicate or changed ownership stays blocked; foreign hosted pages are never
selected. The full context transaction remains under the existing UI mutex.
No app authentication, consent, recording, source or storage logic changes.
Keep the original failed run and frozen tooling; an original-run recovery
requires separately reviewed reconciliation before a fresh run uses new tools.

The Zoom profile increment is Tier 2 because it can follow normal account OAuth
and authorize an exact appointment/meeting through the hosted UI. It uses only
the two synthetic providers and their existing normal Clerk session stores.
Fresh Settings doctor identity, current Clerk identity and explicitly inactive
support-view responses precede a mutation. A pinned read-only staging collector
checks the dedicated host's current binding. A foreign owner, unknown patient
inventory, native capture binding, missing note schema or started meeting blocks
authorization. The existing Dev/John Zoom connection must remain untouched.

This first slice has no bot-media adapter. Profile, account connection and future
meeting authorization are separate observations; bot consent, joining, recording,
fixture delivery, transcript, note and playback gates remain unrun. An OAuth user
checkpoint never collects credentials. A durable intent precedes each click, and
resume rechecks normal UI and scoped collector responses without replaying an
uncertain mutation. Browser scope stays subject to its 15-second freshness limit,
including after the slower management/database collection. The exact bound host
observation is revalidated before authorization and its 120-second expiry is
checked again after dialog waits and at the normal POST. An OAuth timeout
closes the owned browser and reports incomplete authentication; resume only
reconciles a separately completed normal connection and cannot resume that
browser session. A new normal OAuth action requires explicit separate intent.

Recovery closes only owned browser resources and retains uncertain process or
collector ownership. Disconnect is a normal separate account action, not a bot
stop. Before moving the one test host from A to B, separately prove actual bot
stop and use normal disconnection; never silently replace another provider's
binding or run parallel captures. Revert the tooling to disable new executions;
retain already-created journals and any external authorization for explicit
same-run inspection. No production configuration or schema migration is part of
this increment. Exact-head independent review and retained local/live scope
receipts are required; a profile-only pass cannot close overall lab acceptance.

The separate bot-proof increment is Tier 2 test tooling because it gates
synthetic fixture emission on consent and recorder identity. It adds only a
closed metadata contract and an explicitly selected participant proof branch;
the default native branch remains unchanged. No live collector, guessed host
locators, provider mutation or complete bot coordinator is introduced. The
producer must supply real normal host consent and fresh exact-bot/recording
responses with complete Core recording-scoped correspondence. Partial mappings
remain pending; the potential Start Recording response-ID mismatch must be

Recovery never turns absence into stop. Once recording was admitted, unsafe
evidence or a collector exception blocks source restart after admission; only
the same recording's terminal/completion
and exact settled release evidence can establish stop. Closing a participant
does not stop the remote bot. Normal host stop and normal account disconnection
remain separately required before sequential A/B ownership. Revert this tooling
to disable new bot-branch execution; retain evidence and any external bot for
scoped normal cleanup. Tests prove contract rejection and mocked no-schedule
behavior, not a live media or consent gate. A fresh transport rehearsal, real
event/recording mapping, continuous monitor and independent final-head review

The bot source-supervision increment passes the explicit proof through
SourceGroup and supports one combined-fixture Zoom participant. It refuses
mixed paths, concurrent participants and bot pause/resume. The admitted
participant rechecks the same proof gate during playback, with one second
between completed observations and a two-second outer request deadline.
Failure aborts the source group and initiates owned-browser closure. A late
read remains tracked and cannot restart source audio. This is periodic
observation with a measurable detection/closure gap, not continuous capture
proof. Native source behavior and the native proof validator remain unchanged.
An independent three-second watchdog also covers scheduling acknowledgements
and browser status work between proofs; only a successful fresh proof resets
it. Expiry closes owned sources while retaining any unsettled operation.
Recovery retains uncertain read/browser ownership; source closure does not
claim the remote bot stopped. The live collector, normal host actions and
actual media/note verification remain necessary. Revert this tooling for new
runs and preserve frozen existing run inputs; no service deployment or schema
change is part of this increment.
