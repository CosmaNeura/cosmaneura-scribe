# Automatic selection of the visible telehealth call

The owner requested that providers avoid choosing among Chrome/Zoom windows before recording. This follows the merged recording-access repair in PR #341. Mac build 85 has not been signed or installed; its pending binding will be superseded with this reviewed change so the owner receives one replacement of build 84. iPhone 70 continues from the frozen, reviewed PR #341 source because the call picker is a desktop feature.

Risk: Tier 2 for selecting an audio capture target. Consent, the server start decision, source authority, custody, indicators and confirmed stop remain mandatory. This change recommends a source from already-authorized window metadata and never starts recording, checks consent or grants permissions automatically.

Main selects a call only when exactly one current supported window has a recognized Meet call-code or Zoom meeting/webinar title. Generic browser, Meet home and Zoom Workplace windows remain available for deliberate selection. Multiple recognized calls leave the choice unresolved. The provider sees the selected call and can change it. Chrome exposes the visible tab's window title here; selecting a background tab requires bringing that call to the foreground. No browser extension, URL inspection, tab-history access or new OS permission is introduced.

Selections remain tied to the current application, process, window and title. An explicit choice survives only while that complete identity is current. Automatic choices are recomputed from each bounded fresh catalogue. Before Start or Resume spends authority, the target is checked again; a changed target, ambiguous automatic recommendation, permission failure, close or cancellation cannot proceed to capture. Reconnection retains the same call rather than silently selecting a different one. Real window titles and call codes are never written to diagnostics, tests, fixtures, PR evidence or release receipts; tests use synthetic metadata.

Validation covers unique Meet/Zoom recommendations among many unrelated windows, multiple calls, home windows, explicit overrides, stale titles/identities, permission failures, cancellation, close, the preparation-to-recorder handoff and source checks before authority. Shared UI validation covers a concise selected-call display, Change, unresolved selection, consent and pending-action controls. Independent agent review follows the final substantive push, with local type/lint/test evidence because Actions remains disabled by the owner's existing decision.

Release uses only merged main source, the existing signing identities and profiles, fresh renderer/host artifacts, the byte-identical reviewed native package if proven unchanged, and a reviewed replacement Mac 85 binding. Preserve builds 84/83/82 and their receipts. Installation closes Scribe normally, verifies idle twice, retains an independent rollback and the previous installed app, and verifies signatures, helper pins and notarization. It never resets TCC, removes app data, changes keychain state or force-terminates the app.

Physical acceptance remains separate: refresh the existing macOS recording permission through normal settings if needed; confirm the visible Meet/Zoom call is preselected, change/ambiguity behave correctly, consent precedes recording, both audio sources are present, pause/resume stay on the call, finish uploads and opens note review. This plan does not claim those checks have already passed.
