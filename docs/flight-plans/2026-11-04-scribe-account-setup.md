## Closed contracts and recovery

Provider-context accepts setup only as bounded 409 problem JSON, with no-store and
record version 1, no cookies, exactly type/status/setup/request_nonce, and a matching
internal nonce. It re-verifies the same human issuer/subject/session before returning
the signal. Arbitrary errors, extra identity/tenant fields and malformed metadata remain
closed. The receiver adds only the current native revision. Existing registry/clinical
handlers are unchanged; activation belongs exclusively to the Core-context composition.

Activation sends only `action: activate` and a canonical nonzero request UUID to the
fixed Core `/service/v1/agent/scribe/activation`, with a canonical UUID idempotency key,
fresh native human bearer and separately admitted workload bearer. The renderer never
receives either credential or chooses an origin, Doctor, actor, practice or tenant.
Success is a closed version/action/nonce/active state, not recording authority. Private
receiver routes do not alter the public FastAPI OpenAPI schema.

Recovery retains the prior reviewed client and receiver images, closes Core activation
and the selected cohort, and leaves the additive immutable namespace dormant. Preserve
cancellation and revocation evidence. A setup signal never restores cancelled access.
No Stripe configuration, real card charge, membership grant or grandfather entitlement
rewrite belongs to this stack. Synthetic billing exemption uses the existing approved
admin path only after John's approval of the exact practice/action.
