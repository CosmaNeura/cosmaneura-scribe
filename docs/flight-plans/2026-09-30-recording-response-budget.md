# Recording response budget and repeatable virtual tests

Owner: John Clemente. Target: no more than four seconds from Record/Resume to
confirmed input, and from a navigation action to its usable destination. An
immediate spinner, an armed engine without input, or a canceled operation is
not a successful recording start. Slow dependency cases remain failed target
measurements even when recovery and error handling behave correctly.

The September 30 virtual round runs several milestones together: native desktop
critical-path timing, iPhone JS/native-host timing, and nontechnical clinician
persona review of the shared screens. Personas are simulated feedback, not real
clinical acceptance. Existing successful Zoom and iPhone rehearsals were reported
by the owner; they do not establish repeatability or a four-second guarantee.

## Measurement boundaries

Use invented identities, ephemeral storage and generated PCM only. Never open
installed apps, a device microphone, user recordings or external services from
these harnesses. Record product source, injected dependency delays, measured wall
time, completed state and failures. Browser viewport timing is not mobile Safari
or physical iPhone timing. macOS-hosted Swift encryption is real code with fake
transport, driver and storage; native source readiness remains simulated.

Cold open, repeat open, retained request recovery, Record, Pause, Resume and
Cancel are separate measurements. Preserve the same request on uncertain replies.
Record actual input evidence before counting recording success. A failed or
canceled action must remain distinguishable from recording and never invent
missing speech or discard previous captured work.

A prior read-only Mac timing receipt measured a saved-note request at 6,131 ms,
including 1,022 ms native token acquisition and 5,104 ms receiver latency. This is
one historical sample, not a current multi-run server benchmark. Fresh token,
consent, source, lease and storage checks remain in force. Do not claim rendering
changes solve a slow backend or cache authorization to meet a timing target.

## Focused performance change

Risk: Tier 2 by recording-start/cessation effect. At Resume, overlap independent read-only availability with continuation
preparation only after confirmed physical and server retirement. At Start,
overlap a one-use attempt-scoped availability probe with mount authorization
after explicit window choice; controller initialization consumes only that
attempt’s result and the source still performs its separate fresh check. Wait for both branches, including failure, and retain
all fresh source checks, authority budgets, cancellation and explicit window
selection. No audio starts while those prerequisites are unresolved.

The measured controlled desktop profile injects API 300 ms, OS availability
700 ms and native readiness 400 ms. Before the change Start was about 2.4 s
and Resume 4.35 s. Report the retested result in PR evidence and preserve the
900 ms dependency stress case even if it remains over target. Do not substitute
mock readiness for physical capture qualification.

## Delivery and recovery

Keep applicable local tests and exact reviewed/tested source in each focused PR.
The owner staging cohort receives same-identity Mac39/iPhone53 packages after
merge and verification; preserve keys, journals, queues and pending requests.
No production or schema/identity/configuration change is part of this milestone.
An idle installation window is required so an update cannot interrupt recording
or upload. Keep both signed DOB-compatible packages and never reset or uninstall.

Qualification still needed after delivery: physical cold/repeat recording on
Mac and iPhone, source-picker behavior over fullscreen Zoom, and repeated
server-backed screen timings. Actual audio requires a current quiet-room check
with Device Hub/mirroring closed. Do not count the virtual round as that check.
