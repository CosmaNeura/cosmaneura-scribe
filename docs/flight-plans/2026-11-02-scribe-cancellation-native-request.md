# Scribe-only cancellation request and status

Tier 2: account access and PHI boundaries. This client/receiver slice depends on
the reviewed Core cancellation ledger and account processing fence; it creates
no Scribe schema and performs no destruction or shared-login deletion.

The Account menu opens a cancellation review, stops the owned recording before
submission, and requires `CANCEL`. The native signed-in account owns encrypted
CAS retry metadata. An uncertain response retains its original preview and key.
The server's authenticated own-status read recovers after a reinstall. Every
workspace open first checks own cancellation status with a five-second deadline;
a receipt or an uncertain retained request keeps recording controls closed.
Status failure offers Retry access check and never implies permission to record.
This is an access-check deadline, not recording-startup qualification. The
account-level fixed native dashboard opener remains available for read/export
while the receipt's export period is active, independent of a mounted visit.
A changed
account or session revision cannot submit or publish an old request.

The production Core-context receiver verifies the Clerk session and calls only
`/service/v1/agent/scribe/cancellation` with the existing workload identity. This
account-level path has no visit, tenant, doctor, URL or token input from the UI.
The legacy registry receiver denies it. Responses must confirm the Core fence;
the UI never describes intake alone as read-only enforcement.

authorization. Include this receiver source in the next reviewed Core/Scribe

Current Mac127/iPhone93 packages and image22 remain unchanged by this work.

Recovery leaves an accepted ledger request and processing fence intact. Disable
new intake if required; do not re-enable processing, drop the additive ledger,
delete shared Clerk identities, clear retry journals after uncertainty, or claim
that closing the dialog retracts a cancellation. Reverting the client UI does not
undo an accepted cancellation.

The default export window is 90 days. Account Scribe and Core PHI eventually
requires a reviewed custodial inventory and destruction certificate. De-identified
data follows the BAA; audit/BAA/compliance retention is six years and
financial/contract retention seven years. This slice implements no generalized
export generator, destruction worker, certificate issuance or retention purge.
Existing authorized dashboard reads/exports must remain available throughout the
window; that live gate requires the Core fence integration and release validation.

Validation is limited to closed-contract, encrypted retry/recovery, account-switch
and fixed-route tests, TypeScript checks, lint and Swift syntax. No application
launch, live request, credential read, migration, upload or deployment was run.
